## Chosen Scenario

**PawGuide AI** is a German-language pet health advisory application for dog and cat owners. The app helps owners understand their pet's symptoms and prepare informed questions before visiting their veterinarian. It is a pre-consultation informational tool — not a diagnostic replacement.

**Core philosophy:** Inform, never replace. The app displays a one-time disclaimer per chat session and never recommends prescription medications. It may suggest safe, non-harmful supportive home care. It must clearly distinguish between life-threatening emergencies requiring immediate veterinary attention and situations that can be monitored at home.

**V1 scope:** Dogs and cats, German market (Germany, with Austria and Switzerland as V2 markets). Knowledge base grounded in a RAG corpus of German veterinary curriculum literature, validated by Dr. Lund, a licensed German veterinarian.

**Key requirements evaluated:**
- Accurate, medically grounded veterinary information
- Plain language accessible to non-expert pet owners
- Image analysis for visible symptoms
- Emergency escalation recognition
- No prescription medication recommendations
- Safe supportive home care suggestions only
- One disclaimer per session — never repeated

## Overview of Approach

### Part 1: Benchmark Audit & Evaluation Design

Three existing benchmarks were audited — HealthBench (2025), a Veterinary Undergraduate MCQ Benchmark (2025), and TruthfulQA (2021). None were found to fully cover the PawGuide use case, justifying the design of a five-prompt custom evaluation suite. The custom prompts span difficulty from easy baseline to hard safety-critical, covering all eight product requirements and seven identified concern areas.

A complete LLM-as-judge was designed for the GDV emergency escalation prompt — the most safety-critical test case — incorporating a hard safety gate, RAG faithfulness evaluation, communication quality scoring, and constraint compliance checking. The judge was designed with bias analysis and a calibration strategy grounded in Dr. Lund's periodic expert review, supplemented by veterinary working student (Werkstudenten) first-pass review for scalable human oversight.

A professional evaluation memo was written addressing a fictional investor, with appropriate caveats around benchmark contamination, saturation, evaluation scope, and the distinction between controlled test performance and production readiness.

### Part 2: Python Implementation

A complete two-stage evaluation pipeline was implemented in Python using LangChain and gpt-4o-mini:

- **Stage 1:** Production LLM generates PawGuide responses (temperature 0.3)
- **Stage 2:** Judge LLM evaluates each response against quality, RAG faithfulness, and constraint criteria (temperature 0)

Metrics collected include individual scores, safety gate status, criteria pass rates, timing per stage, token estimates, and cost projections. Results saved to structured JSON. Visualization module produces ASCII charts, per-case analysis, and automated pattern detection.

**Key results:** Average score 4.2/5, 100% safety gate pass rate, zero automatic fails. Primary finding: chronic condition completeness gap in TC003 (Feline HCM) requiring prompt engineering fix before deployment.

## How To Run The Code

### Prerequisites

- Python 3.11 or 3.12 recommended (3.14 works with Pydantic warnings)
- OpenAI API key with credits

### Setup

```bash
# 1. Clone or download the project folder
cd lab_llm_judges_[your_name]

# 2. Create and activate virtual environment
python -m venv venv

# Windows:
venv\Scripts\activate

# Mac/Linux:
source venv/bin/activate

# 3. Install dependencies
python -m pip install langchain langchain-openai openai python-dotenv

# 4. Create .env file with your OpenAI API key
echo "OPENAI_API_KEY=your_key_here" > .env
```

### Run The Pipeline

```bash
# Step 7 & 8: Smoke test — verify judge is working
python llm_judge_evaluation.py

# Step 9: Generate responses and run full evaluation (requires API calls ~2-3 min)
python step9_test_dataset.py

# Step 10: Calculate metrics (reads from evaluation_results_raw.json, no API calls)
python step10_metrics.py

# Step 11: Visualize results (reads from evaluation_results.json, no API calls)
python step11_visualize.py
```

### Expected Output Files

| File | Generated By |

| `evaluation_results_raw.json` | step9_test_dataset.py |
| `evaluation_results.json` | step10_metrics.py |
